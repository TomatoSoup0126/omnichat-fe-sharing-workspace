# Harness Engineering

---

# 前情提要

- 之前分享了 Harness Engineering 的概念
  - Prompt Engineering → Context Engineering → Harness Engineering
  - Harness = 指令 + 工具 + 環境 + 狀態 + 驗證
- 將這套 Skill 裝進了 Galleon 專案中
- 兩個月後...

---

# 把它移除了

<v-clicks>

- Harness Engineering 的 Skill 比較偏向為了**一次到位打造完整 Web App** 而設計的
  - 相對沉重，適合一次把所有需求開完、讓 Agent 自行 Loop 並完成實作
- 和 Galleon 的開發方式不同
  - 功能是一個接一個陸續開發的
  - PM 有時候想到什麼加什麼
  - Claude 在這種模式下不需要、也不會主動呼叫這套 Skill

</v-clicks>

---

# 過度約束反而變差？

<v-clicks>

- Claude Fable、GPT-5.5 等新一代模型發布後，開始有文章討論：
  - 過度的指令約束會限制強大模型的表現
  - 模型本身已經夠強，太多規則反而綁手綁腳
- Harness Engineering 的核心正是大量的指令與約束
  - 對較弱的模型有幫助，但對目前推出的頂級模型可能適得其反
  - 而且大量指令本身就會多消耗 token，在高階模型上成本更有感

</v-clicks>

---

# 目前網路上的看法

<v-clicks>

- Harness 不需要消失，但內容需要調整
- 少一點流程指令，多一點邊界約束
  - ~~規定 Agent 怎麼做（流程）~~ → 規定 Agent 不能做什麼（邊界）
  - 用更嚴謹完整的測試取代冗長的步驟指引
- 讓模型自己決定怎麼做，但用測試確保結果正確

</v-clicks>

# 從 checkup 到 doctor

<v-clicks>

- 這個指令剛推出時叫做 `/checkup`
- 目前主要名稱已改為 `/doctor`
- 不只是「診斷」——
  - 在 v2.1.205 之前，`/doctor` 只是開一個**唯讀的診斷畫面**
  - 現在它進化成一個會**主動幫你改善設定**的 Skill
  - 先列出發現的問題，**經你確認後才動手修改**

</v-clicks>

---

# 它會檢查什麼？

<v-clicks>

- **安裝與設定診斷**
  - 安裝健康度：重複安裝、殘留安裝、PATH 問題
  - 無法解析的 settings 設定檔
  - 偵測拖慢速度的 hooks（pre / post command）
  - 檢查發布頻道上是否有新版本
- **精簡 Context 成本**
  - 找出「相對於 context 成本」其實用不到的 Skills / MCP servers / plugins
- **`CLAUDE.md` 記憶檔瘦身**

</v-clicks>

# Galleon UX Review Skill

---

# 它是什麼？

<v-clicks>

- 把最近幾次開發常跑的 **UX review 流程**，包裝成一個 Skill（`.claude/skills/ux-review`）
- 把三件事**封裝成可重複的流程**：
  - 🌐 開 **Chrome 實地操作** 功能 (搭配 Claude chrome extension)
  - 📐 套用 **`ui-ux-pro-max`** 設計知識庫的判斷準則
  - 🔧 依 **Galleon 專案慣例**（i18n `t()`、types → schemas → components）修正
- 用途：審查功能的 UI / 易用性 / 無障礙 / RWD / 亮暗模式，**開發收尾的 UX 把關**

</v-clicks>

---

# 審查流程

<v-clicks>

- **先讀原始碼再看畫面**——很多「怪處」其實原本就有註解說明取捨
- 逐項實地審查（截圖 + 放大細節）：
  1. 進站（沿用登入狀態）
  2. **桌面版**：篩選列、表格、狀態 badge、載入回饋、空狀態、CTA 文案
  3. **確認彈窗**：檢查是否說明後果、帶出操作對象
  4. **RWD 行動版**
  5. **亮 / 暗模式**：文字對比、border 可見度
  6. **Console**：抓 error / warn
- 產出**依影響排序**的報告

</v-clicks>

---

# 產出：依影響排序的報告

<v-clicks>

- 指出**做得好的地方**，再提出**建議改善**
- 每項標註：`ui-ux-pro-max` 類別、問題、具體建議、涉及檔案

</v-clicks>

# 它是什麼？

<v-clicks>

- 一個 **macOS 選單列小工具**
- 即時顯示各個 AI coding 工具的 **token 使用量與額度**，不用逐一切換 App 或開網頁查詢
  - 用 Claude Code / Cursor 會擔心撞到 token 上限
  - 「還剩多少額度、什麼時候 reset」一目了然
- 支援**數十家 provider**：Codex、Claude、Cursor、Gemini、Copilot、OpenAI…

</v-clicks>

---
layout: two-cols
layoutClass: gap-6
---

# 它能顯示什麼？

<v-clicks>

- 📊 **使用量/額度一覽**：各 provider 的使用量、剩餘額度、花費
- ⏳ **重置倒數/預判**：session / 每週 / 每月視窗，估算 token 消耗速度，提醒是否會在重置前先耗盡額度
- 🔀 **Merge Icons**：多個 provider 合併成一個選單，用切換器切換

</v-clicks>

::right::

<div class="h-full flex items-center justify-center">
  <img src="/260730104153.png" class="max-h-100 rounded-lg shadow-lg" />
</div>

---

# 使用重點

<v-clicks>

- 🔐 **不存密碼**：直接取用現有登入 session 與憑證
- ⌨️ **CLI 版**：`codexbar` 指令可腳本化，塞進終端機或 CI/CD
- 🔄 可調**更新頻率**（自動 / 手動 / 1–30 分鐘固定）
- 📦 安裝：`brew install --cask codexbar`

</v-clicks>
